PHASE 8: TOOL EXECUTION PIPELINE (MAJOR FIX)
─────────────────────────────────────────────
Problem: Brain generated TOOL: blocks but never executed them.

Root causes found and fixed:

1. Broca system prompt (brain/broca.js)
   - Old: Generic "you have tools" — LLM guessed wrong names like "touch"
   - New: Full list of all 37 tool names with argument signatures
   - Added rules: one tool per action, treat number-words as names
   - Added examples for create_file, delete_folder, bash

2. Tool extraction regex (routes/chat.js)
   - Old: /TOOL:\s*(\{[\s\S]*?\})/g — non-greedy, stopped at first }
   - This broke on nested JSON: {"tool":"x","args":{"path":"y"}}
   - New: extractJsonBlock() — balanced brace parser that correctly
     handles nested objects

3. Tool execution wiring (routes/chat.js)
   - Added: import { sendToolCall } from '../services/agentBridge.js'
   - After extracting tool calls, now executes them via the agent
   - Results appended to reply as friendly messages

4. Circular import fix
   - server.js imports chat.js, chat.js needed sendToolCall from server.js
   - Created services/agentBridge.js as indirection shim
   - server.js calls setSendToolCall(sendToolCall) to wire the bridge
   - chat.js imports from agentBridge.js — no circular dependency

5. Working directory context injection
   - Chat route now injects workdir path into the LLM message
   - LLM uses correct absolute paths instead of guessing /Users/user/

PHASE 14: MULTI-USER AGENT ISOLATION
─────────────────────────────────────
Problem: All users' tool calls routed to the same agent (no isolation).

Changes:
1. server.js — sendToolCall()
   - Now accepts a token parameter
   - Looks up agent by token first: agentConnections.get(token)
   - Falls back to any available agent if no token match
   - Each user's browser token maps to their specific agent connection

2. server.js — GET /api/agent/status
   - Accepts ?token= query param
   - Returns connection status for that specific token's agent

3. services/agentBridge.js
   - Updated to pass token through to server.js

4. routes/chat.js
   - Passes the user's token from the chat request to sendToolCall

5. src/pages/Chat.tsx
   - Polls agent status with token: /api/agent/status?token=TOKEN

How it works:
- Every browser generates a unique random token (localStorage)
- User connects agent with: npx brain-agent --token THEIR_TOKEN
- Server maps: token → WebSocket connection
- Chat route sends tool calls to the agent matching the user's token
- User A's tools never go to User B's agent
- Works for both signed-up and anonymous users

─────────────────────────────────────

Single server (node server.js) on port 8095:
├── React SPA (dist/) — Home, Chat, NeuralMap, Robot, Memory, Config
├── /api/auth/* — JWT auth (signup, login, pattern, biometric, API keys)
├── /api/brain/* — Brain state, memory, knowledge graph, config

├── /api/sim/* — MuJoCo simulator proxy
├── /api/llm/* — LLM provider status/probe
├── /api/agent/status — Per-token agent connection check
├── /api/workdir — Working directory get/set
├── /businesses/api/* — Business growth sub-app
├── /inventor-studio/api/* — Inventor Studio sub-app
├── /ws — WebSocket (brain state push to browsers)
└── /agent-ws — WebSocket (tool routing to local agents, keyed by token)

Tool execution flow:
User message → POST /api/chat → Broca LLM → TOOL: extraction →
sendToolCall(tool, args, true, token) → agent WebSocket →
local agent executes → result → friendly message → response

Multi-user isolation:
Browser token (localStorage) → agent connection (Map<token, ws>) →
tool calls routed by token → each user's agent is independent
