BUG 4: Businesses growth analysis — "Request failed with status code 500"
  Multiple sub-causes found and fixed:

  4a. Neo4j password mismatch
    Container had NEO4J_AUTH=neo4j/brain_pass but .env had brain_password.
    Fix: Updated .env to NEO4J_PASSWORD=brain_pass

  4b. MongoDB Atlas DNS resolution failing
    Error: querySrv ECONNREFUSED _mongodb._tcp.clusterautopilotwallet...
    Cause: System DNS can't resolve MongoDB Atlas SRV records.
    Fix attempt 1: Added dns.setServers(['1.1.1.1', '8.8.8.8']) in server.js
    Problem: ES module imports are hoisted — dns.setServers ran AFTER mongoose loaded.
    Fix: Created dns-fix.js as separate import, imported first in server.js:
      import './dns-fix.js';  // Must be first — sets DNS before SRV lookups

  4c. MongoDB ensureDb was lazy (connected only on first request)
    Fix: Changed to eager connection at boot:
      await connectMongo(); // In boot() function before brain.init()

  4d. Duplicate mongoose instances
    Cause: businesses app had its own node_modules/mongoose (separate instance).
    Root server.js connected ROOT mongoose, but Growth model used BUSINESSES
    mongoose which was never connected.
    Fix: rm -rf apps/businesses/node_modules/mongoose
         rm -rf apps/inventor-studio/node_modules/mongoose
    Now both sub-apps share root's mongoose instance.

  4e. Vite proxy pointing to wrong port
    Cause: vite.config.ts proxied /businesses/api to localhost:3002 (old separate
    process) but businesses API now runs inside server.js on port 8095.
    Fix: Changed both proxies to target localhost:8095, removed rewrite:
      '/businesses/api': { target: 'http://localhost:8095' }
      '/inventor-studio/api': { target: 'http://localhost:8095' }

  After all 5 fixes: Growth analysis works — "Request succeeded"
